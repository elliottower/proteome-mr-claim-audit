# Amendment 6: identification levels and a recovery pass with external sources

Amendment to `experiments/03_release_resolution/PREREG.md` (frozen 10 October 2026, registered at https://osf.io/2s479), after Amendments 1 to 5 and Deviation 1. It takes effect when the plan's log names the sha256 of this file. Access level: SA1 is coded, gated and judged; routing counts are known; the author has read SA1 abstracts on his page and their highlights. No judge choice or reason has been read, no row of stage A has been coded, and no estimand has been computed.

## Why

The registered estimands measure what a paper documents about the release it used. Two questions remain outside them. First, "unresolved" joins a paper that names a resource with only one release in the dictionary (MEGASTROKE, UK Biobank SAIGE PheWeb) and a paper that names no dataset at all. Second, whether two repeated claims used the same data is a question about the release actually used, which a practitioner can often settle from sources outside the paper: the cited consortium paper, a release page, an accession, or exact counts. This amendment reports both, and leaves every registered estimand unchanged.

## What changes

**1. Identification levels** (secondary analysis SA8, levels). After the last documented stage that runs (stage A, or stage B when it runs), a script assigns every row of the queue one level from its accepted code, its passages and the frozen dictionary definitions (sha256 57f2c5bcef2b63d2d8526d4950c963a5e92e7d56cb75df215b7bbacff9f11e07), with no model:

| level | the row |
|---|---|
| conflict | accepted code `conflicting_identifiers` |
| L1 release identified | resolved under D1 or D2 |
| L4 dataset outside the dictionary | not resolved; `dataset_absent_from_dictionary` |
| L2 one candidate in the frozen dictionary | not resolved; the row's names as written together match the name or an alias of exactly one dictionary row of the side |
| L3 several candidates in the frozen dictionary | not resolved; the row's names as written together match two or more rows of the side |
| L5 no dataset named | absence validated in the current pass: the queue's `name_as_written` (`outputs/coding_queue_2026-10-13.json`) is "not stated", and the row's accepted code of the current pass (agreed by both models, or adjudicated) holds no passage and no name of any dataset for the side, with `release_not_identified` its only release reason |
| name status undetermined | none of the above |

Levels are assigned in the order of the table: the first that applies. A row whose queue name is "not stated" but whose current-pass code holds an unmatched name, or whose absence is not validated as above, is "name status undetermined". A row's names are its name as written in the queue and every resource name in its accepted passages; their candidate sets are joined, and the level reads the joined set. Names are compared after the normalization of Amendment 1 (Unicode NFKC, dashes unified, case folded, whitespace collapsed). L2 means one candidate in the frozen dictionary, not that the resource has one release in the world. Naming is reported apart from attribution: `attribution_unresolved` is a separate column at every level. Reported: rows and repeated pairs by level, per pass. The primary analysis counts only L1. No level above L1 is called an identification.

**2. The recovery pass** (secondary analysis SA9, recovery). After the last documented stage that runs, every record holding a row not at L1 is given to one recovery agent:
- **Model and tools.** Claude Opus 5.5 (`claude-opus-5-5`) through the API, with the vendor's web search and web fetch tools and no other tool. Documents are fetched by plain HTTP request from open-access locations only; no browser is driven, no user agent is altered, and no access control is bypassed. The model string returned is recorded with every response.
- **Input.** The record's sources as retrieved for this stage (abstract, full texts, supplements), the row's fields, and the dictionary definitions. The agent sees no coded answer, judge answer or author mark.
- **Task.** For each row, identify the release actually used, where external sources can establish it, and return each piece of evidence as: the URL, the saved file's sha256, a verbatim quotation, and its type: (E1) a release, accession or version statement in the paper's own sources or reference list; (E2) a registry or repository entry (GWAS Catalog accession, OpenGWAS identifier, release page) tied to the paper; (E3) exact case and control counts, or an exact total, stated in the paper and equal digit for digit to the published counts of exactly one release of the named resource for that endpoint; (E4) a statement in a source the paper cites for the dataset that fixes the release.
- **The evidence link.** With each evidence item the agent gives, each with a verbatim quotation, how the item is linked to this row: the named resource, the endpoint, the ancestry or subset where the resource has several, and the connection to the target paper's analysis (a statement in the target paper's own sources that it used that resource, source or file for this result).
- **Three checks, kept apart.** The agent assesses whether its quotations establish the link. The script checks only that every quotation stands verbatim in its saved file, that an E3 pair of numbers is present and equal, and that the link quotations are given for every required field (resource, endpoint, connection to the target paper, and ancestry or subset when the resource has several). The author's sample (below) checks the substantive inference. Every fetched document is saved and hashed. An item is **linked** when the agent assesses it as linked and the script's checks pass; such links are reported as agent-assessed links with script-checked quotations, never as script-verified links. A row is **recovered** when at least one linked E1, E2 or E4 item names one release and no linked item names another; an E3 match counts toward recovery only together with a linked E1, E2 or E4 item. **Recovery conflict**: linked items name different releases. **Candidate**: the agent names a release, but no linked E1, E2 or E4 item supports it; an exact sample size alone, a single matching dictionary row alone, or a cited source that describes several datasets without a statement in the target paper choosing one, gives a candidate at most. **Not recovered under this protocol**: otherwise. A candidate is never counted as recovered.
- **Author check.** The recovered rows are put in order of row identifier and shuffled by `random.Random(20261029).shuffle`. The author reviews them in that order, seeing the saved sources, quotations and link quotations, and marks each recovery correct only when the evidence establishes the release used for this row's result, including the link above, not merely that the quotations exist. With N recovered rows:
  - the first min(20, N) are reviewed; 0 or 1 incorrect: the pass stands; 3 or more: the pass fails;
  - exactly 2 incorrect: the next min(20, N − 20) are reviewed; the pass stands when at most 3 of all rows reviewed are incorrect, and fails otherwise; when N ≤ 20, 2 incorrect among all N fails the pass;
  - every recovery the author marks incorrect becomes a candidate, whether the pass stands or not;
  - when the pass fails, every recovery is reported as a candidate only.

  Recoveries that stand are described as agent recoveries with sample-based validation, never as individually verified.
- **Reported.** Records eligible, attempted, inaccessible (no open source could be fetched), not attempted because of the ceiling, and not recovered under this protocol, each counted apart; rows and repeated pairs recovered, by level before recovery and by evidence type; recovery conflicts and candidates; the H2 and H2b pair classes recomputed with recovered releases in place of unresolved ones, beside the registered classes. These results are labeled "recovered with external sources" and never replace a registered estimand. The paper never says a release cannot be recovered, and never reads two studies' recovery of the same release as proof that they used the same participants or the same analytic subset.

**3. Search protocol, trial and cost.**
- **Protocol.** The agent's prompt (`prompts/recovery_prompt.md`) and output schema are frozen, with their sha256 logged, before the trial. Per record: at most 40 web search and web fetch calls together, at most 25 saved documents, and at most 300,000 output tokens, reasoning included. A record that reaches a limit ends with the evidence gathered so far, and the limit reached is recorded.
- **Trial.** The pass first runs on 5 records drawn by `random.Random(20261030).sample` from the eligible records in sorted order of record identifier. Its spend per record is written to the log, with a projected cost for all eligible records. The trial's outputs are kept and stand as those records' results. If the protocol is changed after the trial, the change is logged as an amendment before the full run, and the 5 records are run again under it, both results being reported.
- **Order and ceiling.** The other eligible records are run in an order shuffled by `random.Random(20261031).shuffle` over sorted record identifiers. The full pass runs if the trial's projection is at most 600 US dollars, a ceiling of its own on the stage's ledger; otherwise the author decides before it runs, and the decision is logged. The run stops before a request whose reserved bound would cross the ceiling; the records then not attempted are a seeded sample of the order, and are counted apart.

**4. The Maximum claim** gains one sentence: "For rows the papers do not identify, the paper reports how far each gets (a single-candidate name, several candidates, a dataset outside the dictionary, or no dataset named) and, separately, whether an agent with external sources recovered the release used, counted only with verified evidence and checked by the author on a seeded sample."
